# Workspaces

Workspace storage, Host Project registration and Pi cwd grants, project-owned paths, and the hidden Workspace used by Free Conversations. `storage.ts` owns directory persistence, `project-registry.ts` owns local registration and Host path grants, Host config persistence never initializes roots, `paths.ts` owns canonical boundaries/rebasing, and `application-context.ts` is the only `workspaceId → Workspace` resolver.

`free-conversation-storage.ts` schedules user-selected storage moves for the next Host startup. Under the exclusive Host lease it copies and hashes content, retains the original directory as a backup, and replaces the old location with a directory link (Windows junction). The logical session root points directly to the latest destination, so taking an earlier disk offline does not break it. Previous physical locations remain compatibility links while their disks are available. A cancellable plan becomes a non-cancellable switching journal only after the copy is verified. Recovery uses the verified destination even when an earlier disk is offline; only a backup whose source alias was never installed can be restored. The journal is cleared only after the logical root is switched; an interrupted switch is resumed at startup without recopying data. If the previous link is still usable, a switch failure allows startup to continue. Ordinary upgrades and completed migrations do not trigger another move. Failures retain the original storage and a visible error; backups and partial destination copies are never automatically deleted.
