# Shared Configuration
Canonical configuration contracts, persistence, provider metadata, and model capability policy shared by desktop and server runtimes.
Files: `index.ts`, `types.ts`, `paths.ts`, `storage.ts`, `stored-config.ts`, `config-defaults-schema.ts`, `llm-connections.ts`, `llm-validation.ts`, `managed-model-catalog.ts`, `model-fetcher.ts`, `models.ts`, `models-pi.ts`, `preferences.ts`, `pi-user-paths.ts`, `system-instructions-contract.ts`, `system-instructions.ts`, `provider-metadata.ts`, `proxy-env.ts`, `proxy-utils.ts`, `server-config.ts`, `theme.ts`, `user-profile.ts`, `validators.ts`, `watcher.ts`, `cli-domains.ts`, `sync-craft-agent-bash-patterns.ts`; `__tests__/` contains contract and migration coverage.

`stored-config.ts` distinguishes missing data from invalid or inaccessible data. Historical optional fields retain their defaults and unknown fields survive reads. Ordinary writes cannot replace damaged configuration; explicit validated backup restore preserves the original bytes. The caller owns the Host lease before any restore or startup migration.
