# 网文短篇诊断

## 核心原则

**用户留存是网文最重要的指标，是一切评价的底层标准。**

所有诊断都围绕一个问题展开：**读者是否会继续读下去？** 如果不会，文笔、设定、信息量都不构成优点；如果会，粗粝的表达也可以成立。

先判断读者为什么会继续读，再判断文本哪里写得好。不要把"文笔""设定""信息量"当成独立优点；它们必须服务于留存、冲突、推进和兑现。

诊断时区分三类结论:
- **原文事实**:文本明确写出的内容。
- **读者感受推断**:基于文本结构推断的疲劳、期待、困惑或爽感。
- **修改建议**:可执行的结构调整,不直接重写全文,除非用户要求。

如果用户提供的是对标样本、爆款文章或参考文本，先进入拆解模式：只提取结构功能、留存机制、冲突升级方式和兑现节奏，不借具体情节、专名、场面调度或关键台词。

## 诊断流程

1. **识别类型承诺**
   - 判断文本承诺的是爽文、悬疑、情感、反转、恐怖、都市、玄幻、系统、重生、复仇、甜宠还是其他。
   - 检查开头是否尽快交代"谁、处境、问题、欲望、危险或不公平"。
   - 如果类型承诺不清,优先指出;后续评价都依赖这个前提。

2. **找主驱动力**
   - 主角此刻想要什么?
   - 有什么阻碍?
   - 失败代价是什么?
   - 读者期待看到什么变化?

3. **检查读者留存**（最重要的一步，留存决定一切）
   - 前 300-800 字是否产生问题、压力、冲突或情绪钩子——如果没有，读者已经走了。
   - 是否过早解释设定、背景、履历、世界观——解释不产生留存，冲突才产生留存。
   - 是否有"发生了很多，但读者不知道为什么要关心"的问题——没有关心的理由，就没有留存。
   - 每一段、每一章结束时，读者是否有明确理由继续往下读？如果没有，这就是一个留存断点。
   - 留存断点的严重程度：开头留存断点 = 死亡级（读者不会给第二次机会）；中间留存断点 = 流失级（读者会跳读或退出）；结尾留存断点 = 遗憾级（读者不会推荐、不会追下一篇）。

4. **检查平淡来源**
   - 没有明确目标。
   - 阻碍太弱或太抽象。
   - 冲突只停留在解释、寒暄、内心想法。
   - 事件之间只是顺序连接,不是因果推进。
   - 情绪只有一种强度,没有压迫、反击、反转、兑现的变化。

5. **检查爽点与痛点**
   - 爽点前是否有足够痛点、压迫或不公平。
   - 爽点是否由主角行动获得,而不是作者直接赠送。
   - 爽点之后是否带来新局面,而不是马上归零。
   - 如果是非爽文,检查情绪兑现是否成立。

6. **检查结尾兑现**
   - 短篇结尾是否回答或反转开头建立的问题。
   - 是否完成一个状态变化:身份、关系、局势、认知、胜负、情绪。
   - 留白是否是有意余味,而不是没写完。

7. **拆解对标样本**
   - 无损抽取样本的人物、处境、目标、阻碍、事件顺序、信息释放和结尾状态。
   - 标出开篇钩子、读者问题、压力升级、反转点、痛点、爽点和章末/篇末钩子。
   - 区分原文证据、结构判断、可迁移原则；没有证据的判断必须标成推断。
   - 如果用于重写，只迁移结构功能，不迁移具体桥段、道具、专名、台词和场面调度。

## 输出格式

优先用中文输出,按严重程度排序:

```markdown
**总体判断**
一句话说明这段文本最大的问题或最大优势。

**关键问题**
1. 问题名:引用或概括原文证据,说明它如何影响读者留存。
2. 问题名:...

**优先修改**
1. 先改什么:说明改动目标和原因。
2. 再改什么:...

**结构拆解**（仅在有对标样本时输出）
- 样本功能：
- 可迁移原则：
- 不可借用内容：

**可保留之处**
- 只列真正有结构价值的内容。
```

## 常见误判

- 不要因为设定复杂就判断"有吸引力";读者先需要当前冲突。
- 不要把"章末断在一句话"自动视为钩子;钩子必须承诺下一步有意义的发展。
- 不要把"文笔流畅"当成核心评价；流畅但无目标、无阻碍、无变化，仍然会平——读者不会因为流畅而留存。
- 不要按纯文学短篇标准压制网文的类型承诺；网文短篇优先检查读者期待是否被持续管理——留存才是生死线，不是审美线。
