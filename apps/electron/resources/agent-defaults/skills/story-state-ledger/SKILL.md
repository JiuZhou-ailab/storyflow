# 写作状态

## 核心原则

状态台账是写作系统的共享事实层，不是剧情总结。它只记录文本已经确立或用户明确指定的事实、待确认假设、开放问题和回收义务，供灵感、大纲、人物、时间线和章节审查共同引用。

## 台账边界

记录：
- 人物事实：身份、目标、关系、能力、秘密、已知信息。
- 时间事实：事件顺序、时间锚点、持续时间、年龄。
- 世界规则：能力边界、组织规则、资源限制、代价。
- 物件状态：道具归属、损坏、位置、使用次数。
- 伏笔义务：已埋线索、承诺回收、未解问题。

不记录：
- 大段剧情复述。
- 未经确认的润色建议。
- 只出现一次且不影响后续的装饰细节。
- 与文本事实冲突的脑补解释。

## 维护流程

1. **无损抽取**
   - 先从原文或用户说明中抽取事实。
   - 区分“明示事实”“强推断”“待确认”。
   - 保留来源位置或简短证据。

2. **合并去重**
   - 同一实体统一命名。
   - 同义称呼归并，但不要丢失别名。
   - 新事实覆盖旧事实前，必须标记变化原因。

3. **标记状态变化**
   - 记录变化前、变化后、触发事件。
   - 人物知识状态要单独记录：读者知道不等于角色知道。

4. **暴露风险**
   - 前后矛盾。
   - 未回收承诺。
   - 规则例外增长。
   - 时间线空白。
   - 人物动机缺口。

5. **输出给下游**
   - 给大纲：不可破坏事实、待回收承诺、关键限制。
   - 给人物：稳定驱动力、关系状态、知识边界。
   - 给时间线：事件序列、时间锚点、待确认空白。
   - 给章节审查：上一章遗留、本章必须兑现或不能违背的事实。

## 输出格式

```markdown
**台账更新范围**
- 来源：
- 更新类型：新增 / 修正 / 冲突 / 待确认

**实体事实**
| 实体 | 类型 | 事实 | 状态 | 证据 |
|---|---|---|---|---|

**事件事实**
| 事件 | 顺序/时间 | 参与者 | 结果 | 后续义务 |
|---|---|---|---|---|

**开放问题**
1. 问题：为什么重要 -> 需要谁确认或在哪补。

**下游提醒**
- 大纲：
- 人物：
- 时间线：
- 章节：
```

## 常见误区

- 不要把台账写成读后感；它应当可被后续任务直接引用。
- 不要把推断伪装成事实；推断必须标注确定性。
- 不要删除旧事实来掩盖矛盾；先标记冲突，再提出修复。
- 不要让每个 skill 各自维护私有事实表；共享状态应收敛到台账。
