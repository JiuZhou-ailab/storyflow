# 大纲生成

## 核心原则

大纲不是剧情摘要，而是读者期待的管理计划。它要明确每个阶段的目标、阻碍、状态变化、信息释放和兑现节点，并为人物、时间线和章节单元留下可检查的契约。

## 依赖关系

优先使用这些上游输入；缺失时基于合理假设补齐并标注：
- 故事核：类型承诺、主角欲望、核心矛盾、可兑现看点。
- 人物驱动力：主角目标、弱点、关系张力、反派/阻碍策略。
- 篇幅目标：短篇、单章、N 章连载、长篇卷纲。
- 共享状态：已有设定、时间线、人物事实、不可破坏事实。

## 生成流程

1. **锁定主线问题**
   - 故事从哪个问题开始。
   - 读者最想看到哪个答案或结果。
   - 最终兑现什么状态变化。

2. **划分阶段**
   - 短篇：开场钩子 -> 冲突升级 -> 关键选择 -> 反转/兑现 -> 余味。
   - 连载开篇：钩子 -> 初次行动 -> 小兑现 -> 新威胁 -> 持续目标。
   - 长篇：卷目标 -> 阶段目标 -> 章节单元。

3. **设计因果链**
   - 每个节点必须由上一节点触发。
   - 每个转折必须改变信息、关系、资源、危险或目标。
   - 关键胜负必须来自角色行动、前文铺垫或稳定规则。

4. **安排兑现节奏**
   - 痛点和爽点成对出现。
   - 解释不单独成章，必须附带选择、冲突或后果。
   - 每个阶段至少有一个阶段性结果。

5. **切分章节/场景单元**
   - 每个单元都要有目标、阻碍、行动、信息释放、状态变化或钩子。
   - 上一单元留下的问题、危机、承诺或情绪，下一单元开头必须接住。
   - 如果单元只解释设定、寒暄、重复心理活动，优先合并、压缩或改成冲突场景。

6. **标记检查点**
   - 需要人物设计支撑的节点。
   - 需要时间线校验的节点。
   - 需要伏笔回收的节点。
   - 容易水或跳因果的节点。

## 输出格式

```markdown
**大纲前提**
- 类型承诺：
- 主线问题：
- 结尾兑现：
- 篇幅假设：

**结构总览**
1. 阶段名：目标 -> 阻碍 -> 转折 -> 状态变化
2. ...

**章节/场景规划**
| 单元 | 目标 | 冲突 | 信息释放 | 状态变化 | 钩子/兑现 |
|---|---|---|---|---|---|

**单元检查**
- 承接：
- 本单元目标：
- 阻碍升级：
- 章末/场末动能：

**依赖与风险**
- 人物依赖：
- 时间线风险：
- 因果风险：
- 可删减节点：
```

## 常见误区

- 不要把“然后发生”当作推进；推进必须改变状态。
- 不要先排章节数再硬塞剧情；先确定阶段功能，再切章节。
- 不要让反派只在结尾出现；阻碍策略需要贯穿。
- 不要把所有兑现押到结尾；网文需要阶段性回报。
