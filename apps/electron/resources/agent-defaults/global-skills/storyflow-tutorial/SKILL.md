# Storyflow 使用教程

## 核心原则

教程应该按用户当前目标讲，不要一次性讲完整功能清单。先判断用户想完成什么，再给最短路径、一个可复制示例和下一步操作。

始终围绕这五个真实边界组织说明：

- 对话：用户描述当前要完成的结果。
- Skills：提供完成任务的方法与流程。
- Sources：提供外部资料和可追溯证据。
- 项目文件：保存大纲、人物、正文和连续性状态。
- 系统指令：在“设置 → 偏好”中维护跨项目生效的长期协作规则。

## 教程流程

1. 先询问用户当前最想完成的目标：开始写作、续写、改稿、查资料、分析项目或整理文件。
2. 根据当前项目，只用 3-5 条说明完成该目标的最短路径。
3. 展示一个可直接复制的输入示例。
4. 说明什么时候使用 `/` 选择 Skills，什么时候用 `@` 选择 Sources 或文件。
5. 如果会修改项目文件，提醒用户在变更预览中核对后再接受。
6. 只有当用户询问长期偏好时，才介绍“设置 → 偏好 → 系统指令”；不要把它与单次对话要求混为一谈。

## 常见入口

- 新建对话：从开场按钮选一个目标，或直接描述任务。
- 使用 Skills：输入 `/` 选择专门流程，例如大纲、人物、正文写作、正文修订。
- 使用 Sources：输入 `@` 选择数据源或文件，让回答基于外部资料。
- 持续写作：把大纲、人物、正文和状态文件留在项目里，后续对话继续读取。
- 审核改动：先看变更预览，再决定接受或继续调整。
- 长期协作规则：在“设置 → 偏好 → 系统指令”中填写，下一次发送消息时生效。

## 输出要求

- 每次只教当前目标需要的内容。
- 回答要短，优先给可执行动作。
- 优先使用当前界面的中文名称，并明确指出入口位置。
- 不要把教程写成产品宣传。
