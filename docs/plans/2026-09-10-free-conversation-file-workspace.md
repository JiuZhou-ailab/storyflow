# 自由对话侧边工作区：对话文件

日期：2026-09-10
状态：已按 [GitHub Issue #38](https://github.com/JiuZhou-ailab/storyflow/issues/38) 实现并完成本地验证；未推送。

## Problem Statement

自由对话独立于项目，已经拥有会话文件、Explicit Attachments 和私有默认工作目录，但桌面右侧工作台的入口依赖项目。用户在对话中上传材料或生成文件后，缺少稳定的浏览与预览位置，需要回翻消息或打开文件管理器。

现有会话文件树扫描整个会话存储目录，混合工作文件、附件和运行数据，不能直接作为面向用户的“对话文件”。自由对话需要围绕当前会话呈现材料和成果，同时保持 Runtime Domain 的归属边界。

## Solution

为桌面自由对话增加与项目对话同位置、同图标语义的右上角展开／收起入口。打开后呈现“对话文件”：文件列表展示本次对话的工作文件与已发送附件，内容区域复用现有只读预览。

首版实现一个完整闭环：展开侧栏 → 找到文件 → 预览或用系统应用打开 → 文件变化后刷新 → 切换会话后只显示目标会话内容。

首版明确不提供内置编辑。用户可以通过系统应用编辑可变工作文件；返回后侧栏刷新磁盘内容。附件原件保持不可变。无需创建、绑定或升级为项目。

## User Stories

1. 作为自由对话用户，我希望没有任何已注册项目时仍能打开对话文件，以便使用对话产物。
2. 作为自由对话用户，我希望在熟悉的右上角位置展开与收起侧栏，以便控制阅读空间。
3. 作为自由对话用户，我希望侧栏默认收起，以便普通问答保持简洁。
4. 作为自由对话用户，我希望看到当前对话生成并保存的文件，以便直接找到成果。
5. 作为自由对话用户，我希望看到已经发送的附件名称，以便重新查看输入材料。
6. 作为自由对话用户，我希望同一附件只显示一个原件入口，以免把缩略图或转换副本误认为额外材料。
7. 作为自由对话用户，我希望保留工作文件的目录层级，以便区分不同目录里的同名文件。
8. 作为自由对话用户，我希望点击支持的文件后在侧栏预览，以便对照内容继续讨论。
9. 作为自由对话用户，我希望无法预览的工作文件与下载成果仍能用系统应用打开，以便使用已有工具。
10. 作为自由对话用户，我希望明确知道首版预览只读，以免误以为可以在应用内保存修改。
11. 作为自由对话用户，我希望外部修改工作文件后能看到最新内容，以便继续对话。
12. 作为自由对话用户，我希望文件列表随 Agent 或外部应用的文件变化更新，以免反复关闭重开。
13. 作为自由对话用户，我希望新会话说明文件会出现在哪里，以便理解空状态而不被要求创建项目。
14. 作为自由对话用户，我希望切换对话后列表与预览立即切换归属，以免把上一会话的内容用于当前会话。
15. 作为使用多个对话面板的用户，我希望侧栏跟随当前聚焦的会话，以便清楚知道正在查看谁的文件。
16. 作为自由对话用户，我希望文件缺失、读取失败与目录为空有不同反馈，以便判断是否需要重试。
17. 作为自由对话用户，我希望项目文件、内部日志与未发送附件不自动进入列表，以便列表保持明确范围。
18. 作为项目对话用户，我希望自由对话侧栏不会改变已有项目目录、编辑与版本管理行为。

## Implementation Decisions

### 归属与复用

- 遵循 ADR 0006 和 Runtime Domains 领域词汇：Free Conversation Domain 继续由隐藏的 Application Workspace 承载，每个会话拥有私有默认工作目录。右侧工作区是会话内容的 UI 投影，不是新 Project 或新 Runtime Domain。
- 复用现有侧栏布局、缩放约束、文件树交互、文件预览器、文件打开／定位动作，以及会话文件查询和监听设施。只把必要的文件呈现能力从项目显示条件中分离，不整体启用项目工作台。
- 文件身份来自当前会话及其真实存储位置；不增加附件数据库、产物登记表、第二套文件监听服务或新的 Agent runtime。
- 项目上下文与文件可访问权限仍是不同维度。本次列表限定“显示什么”，不改变 Agent 的本机文件权限。

### 文件范围

| 内容 | 首版规则 |
| --- | --- |
| 工作文件 | 展示当前会话私有默认工作目录内的非隐藏文件，保留相对目录结构；目录本身存在但没有可展示文件时按空集合处理。 |
| 下载成果 | 展示现有会话下载区域内的非隐藏文件，使用单独的“下载”目录呈现，不与工作文件按文件名合并。 |
| 已发送附件 | 从已持久化用户消息的附件记录确定成员，展示其存储原件与原始显示名；同一存储原件去重，不按同名文件去重。 |
| 派生表示 | 缩略图、转换文本和模型输入副本不成为独立文件项；已有预览器可在明确的预览能力内使用派生表示，但不能把它当原件导出或打开。 |
| 草稿附件 | 输入框中尚未发送的附件留在原有输入区，不进入侧栏；发送后才进入。 |
| 范围外内容 | 会话转录、内部计划、长工具响应、日志、缓存、元数据、兄弟会话目录，以及 Agent 仅访问过的外部文件均不进入列表。 |

- 固定呈现“工作文件”“下载”“附件”三个分组，仅显示有内容的分组。分组由存储职责决定，不引入由模型猜测“材料／成果”的分类器。
- 文件夹使用目录优先、名称排序；附件保留消息首次出现顺序。不同来源的同名文件分别保留。
- 已发送附件复用现有不可变原件及历史附件兼容解析；缺失原件仍保留附件项并标明不可用，不回退到任意外部同名文件。遵循 ADR 0009，不改写或迁移用户原件。
- 不扫描隐藏 Workspace 的根目录，也不因会话工作目录后来指向外部位置而自动展示整个外部目录。工作文件范围固定为会话自有的私有工作区域，下载和附件通过各自现有存储契约解析。
- 服务端从显式会话标识解析文件范围；渲染层不接受或拼接任意扫描根目录。符号链接不得使枚举越出选定的内容区域，沿用现有路径验证能力。

### 查询与监听契约

- 在现有会话文件查询上提供显式的“对话内容”视图：输入为当前会话标识和内容视图，输出为分组文件条目及是否截断。附件成员由服务端读取持久化记录，不能为了侧栏让渲染层加载整份会话转录。
- 未请求新视图的调用方保持现有返回契约，避免改变会话信息弹层及其他既有消费者。新增视图不修改会话持久化格式。
- 新视图沿用现有 500 个文件／目录条目的单次树预算；预算到达时返回截断标记并显示“文件较多，仅显示部分内容”，不得让截断看起来像完整列表。首版不实现分页或新的虚拟文件索引。
- 查询失败必须与成功空列表区分。读取失败显示错误与“重试”；消息元数据无法读取时，整个查询报错，不静默丢掉附件分组后宣称完整。
- 复用会话文件变更事件刷新列表。已发送附件成员还需在消息成功持久化后刷新，不能仅依赖附件文件先于发送创建的文件事件。
- 侧栏关闭时释放本视图的监听与预览工作，打开时重新读取；重连后恢复当前会话的查询与监听。若同一客户端另有会话文件消费者，挂载／卸载不得互相取消仍被使用的订阅。

### 入口、布局与空状态

- 支持现有桌面宽布局的自由对话页面。按钮提示和无障碍名称使用“展开右侧栏／收起右侧栏”，通过展开状态表达当前开关值，可用键盘触发。
- 沿用现有工作区的文件标签栏、内容区与右侧可折叠目录；“对话文件”作为区域名称，不另建标题栏或文件树样式。一次只预览一个文件，不增加多文件标签管理。
- 自由对话在每次应用窗口创建时默认收起；窗口内切换自由对话保留开关状态。不新增持久化设置，不修改项目工作台的既有展开偏好。
- 有文件但尚未选择时，内容区域显示“选择文件以预览”。无文件时显示“本次对话的附件和生成文件会显示在这里”，不出现创建项目或绑定目录提示。
- 尚无实际会话标识时允许打开侧栏并显示空状态，不因点击按钮而创建会话或磁盘目录。
- 文件到达不会自动展开侧栏或抢占当前预览。用户手动打开，或点击属于本次会话列表范围内的聊天文件链接时，才展开并选中文件；范围外链接继续使用既有打开流程。
- 紧凑布局沿用当前会话文件抽屉入口，不新增常驻双栏；抽屉中自由对话的文件范围与宽布局保持一致。首版不改造项目紧凑布局。

### 预览、编辑与打开

- 内置能力为只读预览：具体格式支持服从现有文件分类与预览器，不新增格式解析、转换器或编辑器。图片、PDF、可预览文本等复用已有呈现；工作文件与下载成果不支持的格式显示系统打开入口，附件不支持的格式显示“暂不支持预览”及定位入口，不承诺 Office 原生编辑。
- 工作文件与下载成果提供“打开文件”“打开文件位置”，复用现有平台动作；这些动作始终作用于当前选中条目的真实路径。
- 附件预览和定位使用存储原件。允许定位原件，但不把不可变附件原件交给可写系统编辑流程；首版不为附件新增可编辑副本管理或专用导出动作。
- 首版没有编辑按钮、保存按钮、自动保存、未保存草稿、项目版本快照或选区 AI 改写。需要修改时，用户对可变工作文件执行系统打开；本功能不写入任何文件内容。
- 当前预览文件在外部发生变化时刷新预览；删除或移动后停止展示旧内容，明确提示“文件已不存在”，不得自动打开同名替代文件。目录查询或预览失败不关闭聊天，不标记会话执行失败。

### 会话切换与状态

- 单个窗口的侧栏跟随当前聚焦的自由对话；会话标识变化时立即清空旧列表、旧选择和旧预览，再加载目标内容。首版不记忆每个会话最后预览的文件。
- 旧会话查询、预览读取或监听事件即使晚到，也不能写入新会话的界面；所有异步结果以发起时的会话／文件身份校验。
- 切换至项目或非对话页面时卸载自由对话内容，恢复该页面的既有布局；不将自由对话文件注册到项目或改变会话归属。
- 首版没有内置编辑缓冲，因此切换文件、会话或关闭侧栏不产生“保存／放弃”对话框。外部应用的保存由外部应用负责，文件监听只刷新磁盘事实。

## Testing Decisions

主要测试边界为真实 Electron 界面 → 现有 preload／会话文件 RPC → 隔离临时目录中的真实文件。复用已有无项目启动、会话侧栏、文件链接预览和重连检查的离线测试方法，集中验证一个完整用户闭环。该测试边界已确认。

在服务端会话文件 RPC 边界补充一组聚焦行为测试，验证来源范围、不可变附件、查询错误、符号链接边界和截断标记。复用现有有界会话文件树测试设施，不为纯布局或每个组件逐一添加测试，不用源码字符串断言证明归属隔离。

### Acceptance Criteria

1. 零注册项目启动，打开自由对话后右上角可以展开／收起“对话文件”，不会注册项目或改变 Runtime Domain。
2. 新窗口默认收起；侧栏展开后切换自由对话仍保持展开；项目侧栏偏好不被改写。
3. 空会话和未创建会话均显示指定空文案；点击侧栏不创建会话、目录或项目。
4. 在隔离目录中放入工作文件、下载成果、已发送附件、未发送附件、转换副本和内部运行文件，界面只展示规定成员；其他会话和项目文件不出现。
5. 同名不同路径文件分别保留；同一附件原件多次发送只出现一个入口；原件缺失显示不可用而非隐式回退。
6. 上传后未发送的附件不出现；发送并持久化后出现，即使文件创建事件早于消息持久化。
7. 支持格式能在侧栏正确预览；不支持格式有明确回退；没有编辑或保存入口。浏览、预览和会话切换前后，附件原件内容哈希不变。
8. 对工作文件执行打开／定位，传给系统动作的路径与当前条目一致；附件原件不进入可写系统打开流程。测试捕获系统动作，不实际修改用户系统文件。
9. 外部创建、修改、删除工作文件后列表和当前预览更新；删除后的旧预览不继续显示。新文件不会自行展开侧栏或替换用户选择。
10. 点击属于当前会话范围的聊天文件链接，展开并选中目标；范围外链接保持原有行为，不被收集入侧栏。
11. 快速从会话 A 切到 B，并让 A 的查询、文件读取和变更事件延迟返回，界面始终只展示 B 的数据；多面板切换焦点也满足该条件。
12. 关闭侧栏、切换域及重连不会留下旧订阅或打断其他有效文件消费者；重新打开能读取当前文件事实。
13. 读取失败显示可重试错误，成功空结果显示空状态；预览失败不会误报为文件不存在或会话执行失败。
14. 超过 500 个条目时返回有界结果且提示截断；测试不能把“只返回前 500 项”视为完整成功。
15. 枚举不跟随越出内容区域的符号链接，不接受渲染层指定任意根路径；当前 OS 权限与其他合法文件打开能力不因列表范围改变。
16. 紧凑布局使用既有抽屉且展示相同会话内容；宽布局按钮可键盘操作，名称和展开状态正确。
17. 项目对话的文件树、编辑保存与版本管理通过既有相关回归检查；本功能不改变项目会话的目录根或文件归属。

实现阶段运行聚焦 RPC 行为测试、单条完整 Electron 集成检查及受影响包的类型检查。文件变化由测试进程写入隔离目录触发，默认不调用外部模型或付费 provider；验证的是本功能消费真实文件与持久化附件的行为，不宣称已经验证模型产物质量。

## Out of Scope

- 内置文本／Markdown／Office 编辑、自动保存、修改冲突解决、项目版本管理和选区 AI 改写。
- 新建、重命名、删除、拖动导入文件，以及附件可编辑副本、专用另存为／导出流程。
- 自动把聊天文字转为文档、扫描工具调用历史收集外部路径、模型驱动材料／成果分类。
- 跨会话文件聚合、跨项目目录挂载、项目创建／升级入口及任何 Runtime Domain 转移机制调整。
- 新存储格式、历史会话文件迁移、全文索引、分页查询、新文件格式解析器或新的监听服务。
- 每会话预览历史、多标签编辑、持久化侧栏开关设置、独立移动端布局。

## Further Notes

- 首版只读预览复用现有文件呈现能力。项目编辑保存编排包含项目版本相关职责，内置编辑不属于本次最小交付，不得仅隐藏版本按钮后直接接入整套项目保存链路。
- 工作区主语是“当前对话的材料和成果”。文件分组是已有存储职责的呈现，不新增与 Project 并列的业务实体。
- 功能作为一个可独立交付切片实现，无需先拆成多个 ticket。回滚删除新增入口和内容视图即可，不涉及用户内容回滚或数据迁移。

## Implementation and Verification

- 文件范围集中在 `packages/server-core/src/handlers/rpc/session-conversation-files.ts`；沿用现有 RPC，添加显式内容视图及独立消费者订阅。附件成员仍来自持久化消息，条目携带磁盘修改时间以避免无关变化重置预览。

- `bun run typecheck:all` 通过；最终渲染层修复后再次执行 Electron 类型检查与构建通过。
- 全量测试流程的常规部分 5502 通过、11 跳过；HTTP 与隔离部分累计 272 通过。隔离搜索测试的旧模块 mock 已改为保留真实导出，修复后从该阶段补跑剩余测试全部通过。
- `bun e2e/core/conversation-files.ts` 通过：零项目入口、空状态、真实文件变化、已发送原件去重、列表及预览读取重试、快速会话切换、窗口重建默认收起、重复文件链接、宽窄布局双向切换，以及精确系统动作路径。系统动作在 preload RPC 边界捕获，不启动编辑器或 Finder；不调用模型。
