# Pi 0.87.1 upgrade acceptance (#48)

Target: [Pi 0.87.1](https://github.com/earendil-works/pi/releases/tag/v0.87.1),
public AgentSession. Spec: [#48](https://github.com/JiuZhou-ailab/storyflow/issues/48).
Implementation started from `2acf8f36ce17faaece765850c54f18ede5846efb` with concurrent
uncommitted work present. The final commit must exclude unrelated changes.

## Responsibility changes

Deleted the JSONL sanitizer, subscribed-message mutation, encrypted-error retry
wording, automatic startup-failure pointer reset/context seeding, and product
compaction-default module. Pi owns history projection, retry context edits and
native compaction settings. Explicit summary caps and call_llm limits, incomplete/failed outcomes,
create-only publication and exact source references remain business contracts.

Retained Host permission checks, credential persistence, rewind identity mapping
and transaction compensation, process transport, and project execution trust.
The two native resource loaders separate executable project resources from Skills.
Dynamic new tool schemas still require resource reconstruction; active-tool toggles
cannot register unknown schemas. Mini queries retain disposable AgentSession:
managed fallback and cancellation already share its native budget/settlement;
direct ModelRuntime streaming alone would require a second recovery loop. No new
query framework or experimental harness was introduced.

See [patch decisions](../packages/pi-agent-server/patches/README.md) for every
retained/retired patch area and reproducible upstream gaps. No claim of zero patches,
lower model cost or improved creative quality is made.

## Data and rollback boundary

The checked-in `src/fixtures/pi-0.84.4-history.jsonl` was generated by unpatched
0.84.4 SessionManager. 0.87.1 opens it without replacing its bytes. New native
context_edit entries persist a projection separately from original content; reopening
0.87.1 retains both original bytes and the projected model context.

**0.84.4 silently ignores context_edit. Executable-only rollback is unsafe.**
An isolated run opened the same upgraded copy with both installed SDKs: 0.87.1
projected the replacement, 0.84.4 exposed the original message. Opening an untouched
backup with 0.84.4 restored the original context without changing the backup bytes.

Before release, stop all writers and snapshot the product session metadata and its
`.pi-sessions` directory together. Keep this paired backup outside the live session
path. To roll back, stop writers again, archive the upgraded pair under a separate
path, restore the pre-upgrade pair, then start the old executable. Never point the
old executable at upgraded history. Work created after upgrade stays archived for
0.87.1 reading/export; it is not merged or discarded. No dual-write migration exists.

The compatibility test covers valid v3, aborted/partial tools, orphan results and
an unreadable header and an empty file. Pi's native reader can skip malformed individual lines or
append a missing trailing newline; this is not a promise to repair every corrupt
record. Unrecognized nonempty files fail through SessionManager.open; existing empty files
are rejected before Pi can initialize them.
No product cleaner rewrites them. Older pre-v3 files may invoke Pi's own migrations
and require the same paired backup; they are outside the verified v3 range.

restart and selected-message branch/rewind. Compare stored metadata and Pi leaf
before/after restart. Block rollout until these checks and paired-backup restoration
on the release storage layout have evidence. This implementation does not deploy
or advance the experimental runtime readiness gate (#28).

loopback providers. The full suite and desktop packaged QA were not repeated for
this follow-up. Revert this cleanup commit to restore the previous policy; no
persisted format or user settings changed.
