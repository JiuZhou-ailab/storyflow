# ADR 0024: Agent 改动即最终结果，文本统一自动保存

状态：Accepted
日期：2026-10-14

本决定取代 ADR 0007 非目标中“不移除版本历史与 diff 审阅能力”一条。

## 背景

项目工作区曾叠加三套机制：用户侧版本快照（隐藏 git 仓库 + 版本历史面板）、Agent 改动审阅
（接受/拒绝、整轮撤回、撤销栈、正文内联审阅 diff）、文本手动保存（保存、另存为、恢复副本）。
它们分别补偿“Agent 可能改错”和“用户可能丢稿”，但都要求用户理解一套额外的状态模型，并让
同一份文件在磁盘、草稿、快照、待审阅四处各有一个版本。

第一性地看，Agent 真正需要的只有一个事实：上一轮之后，哪些文件被别人改过，改之前要重读。
用户真正需要的也只有一个保证：自己的输入不会被静默覆盖。

## 决策

1. **Agent 改了就是改了。** 不提供接受/拒绝、撤回或撤销栈。工具调用的文件改动只做只读展示
   （改动摘要卡片与多文件 diff 视图），帮助理解，不构成第二个待定状态。
2. **文本统一自动保存。** 磁盘是唯一事实源，版本号为内容 sha256；保存是 CAS，冲突时保留
   草稿并只给“保留我的版本 / 使用磁盘版本”两个选择。空版本号表示独占重建已删除文件。
3. **工作区新鲜度由服务端按会话生成。** `WorkspaceFreshness` 在回合结束时记录 md/txt 文件的
   `size:mtime` 清单作为基线，下次发送前与当前清单对比，把外部增删改以一次性
   `<workspace-brief>` 放入当前回合上下文（不持久化进对话）。稳定的系统策略只说明如何对待该块，
   保持 prompt 前缀可缓存。
4. **不再创建或依赖任何 git 仓库。** 产品不在项目根 `git init`，不读写快照 refs，也不改变用户
   自己的 Git HEAD、index 或工作区状态。

## 约束与取舍

- 清单只在内存：重启后第一次发送只建立基线，不产生 brief。
- 用 `size:mtime` 而非内容哈希：误报只会让 Agent 多读一次文件，换来有界的 IO（上限 5000 项、
  2s 超时、并发 stat 32）；超限或失败时不产生 brief 并丢弃基线，而不是给出不完整的事实。
- Agent 回合进行中用户的修改会被回合末基线吸收；重命名表现为删除 + 新增。
- 旧数据原样保留，不迁移不删除：项目状态目录下的 `history.git`、旧位置的快照 refs、
  `text-recovery/` 恢复副本目录。若未来要清理，需要单独的数据生命周期决定。

## 后果

- 移除了 git 快照引擎、版本 RPC/DTO 与相关 UI、审阅子系统和手动保存入口，客户端不再向发送
  请求附加新鲜度上下文。
- 用户若需要可回溯历史，使用自己的 Git 或同步盘；Storyflow 不与之竞争。

重审条件：出现无法由用户自有版本工具覆盖的、可验证的丢稿或误改事故模式。
