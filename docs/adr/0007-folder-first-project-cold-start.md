# ADR 0007: 项目以真实文件夹和显式 Skills 冷启动

状态：Accepted
日期：2026-07-24
修订：2026-08-27

## 背景

过去的新项目创建要求选择一个 Method Pack。它同时决定项目类型、目录、模板文件、内置 Skills、
写入规则、聊天首屏和导出分类。这个聚合概念把相互正交的关注点压成一次选择，并在创建或加载时
改写用户文件夹；用户尚未表达目标，系统却先替用户决定了结构。

项目的长期事实源其实只有两个：用户真实拥有的文件夹，以及用户显式选择或安装的 Skills。
聊天引导、文件审阅和导出都可以从这两个事实源工作，无需第三套项目画像。

## 决策

- 新项目创建只建立运行所需的隐藏宿主状态，`workingDirectory` 指向项目根。
- 全局注册记录的 `id` 是稳定 Project ID；`rootPath` 只是可变 locator。目录内旧
  `WorkspaceConfig.id` 是兼容元数据，不能覆盖 Host 身份。目录移动后只允许用户显式 relink，
  不自动重建旧路径或合并两个 Project。
- Project catalog 读取必须无副作用。升级迁移可以把没有目录 fingerprint 的旧 Host 记录绑定到其
  已保存且仍可安全验证的原 locator，以延续旧版本已经授予的目录权限并固定后续替换检测；不能自动
  采纳其他路径，无法安全验证时仍要求用户显式 relink。
- 所有本地 Project 创建入口都必须经过同一 Project registry；低层 Host 注册持久化只写注册记录，
  不得隐式初始化、重建或修复 Project 根目录。
- 不自动创建领域目录、模板文件、`.pi/skills`、写作 manifest、pack lock、Git 仓库或起始对话。
- 空白项目提供四个平级入口：描述目标、导入已有内容、新建文件、选择 Skill。
- 项目侧边栏始终展示真实文件树；文件名和目录名不决定项目能力。
- 文件审阅覆盖项目内实际变更，不因未知目录或文件类型被过滤。
- 导出由用户显式选择文件或文件夹，保持原目录结构，不按推断类别合并或改写内容。
- Skills 是按需能力，不负责在安装前替用户生成项目目录。需要固定结构的 Skill 应在执行时说明并
  请求相应文件操作，而不是通过项目类型隐式生效。
- 旧 `craft-writing.json` 仅保留只读识别兼容：可以识别旧写作项目，但不再执行旧写入策略，
  并忽略 Method Pack 元数据；加载时不得修复、补建或删除用户文件。
- 删除 Method Pack 注册表、脚手架、内置写作 Skill 镜像、验证器和修复器；Workspace DTO 不再暴露
  `projectType` 或 `methodPackId`。

## 后果

优点：

- 项目目录完全由用户行为和真实内容演化，创建与打开都是可预测、无损的。
- Skills、文件结构、审阅和导出各自拥有独立契约，减少跨层条件分支。
- 新项目不需要先理解 Storyflow 内部方法模型，冷启动可以从最小意图开始。

代价：

- 空白项目初次打开时没有示例内容，产品必须提供清楚但不强迫的下一步入口。
- 旧写作项目仍有一层明确标注的只读兼容代码；删除该层需要单独的数据生命周期决策。
- 依赖固定目录的旧工作流需要迁移为显式 Skill 指令或由用户保留现有文件结构。

## 非目标

- 不删除、复制、迁移或重排既有项目中的文件、目录、manifest 或 Skills。
- 不移除 Markdown 编辑、版本历史、文件提及或 diff 审阅能力。
- 不为尚未出现的项目类型重新引入模板选择器、配置画像或目录推断系统。
