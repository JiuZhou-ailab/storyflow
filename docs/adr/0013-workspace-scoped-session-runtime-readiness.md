# ADR 0013: 会话运行时就绪按工作区分片

状态：Accepted
日期：2026-07-31

## 背景

ADR 0002 把桌面启动拆成"传输/工作区外壳就绪"和"Agent 运行时就绪"两个阶段，并让依赖会话的 RPC 域
统一注册到一个初始化门（`createInitGatedRpcServer`）之后。该 ADR 当时已指出遗留代价："全局会话
发现在首帧之后仍有绝对成本。"

标准 fixture 上这个代价现在可以被精确测量。ActivityRail 在 ~1.1s 可交互，但整个会话/搜索 RPC 面
直到 ~2.75s 才可用：

- 刚可交互时发起的 `getSessions` 耗时 2752ms，紧随其后的第二次调用只要 70ms。
- 点击项目后并发发起的 `searchWorkspace` 与 `getSessions` 双双耗时 ~3000ms；3ms 后再发一次相同
  搜索只需 152ms。
- 搜索在 12ms 就进入 `searching`，直到 2861ms 才 `complete`。

渲染进程在这 2.6s 内是空闲的（CPU profile 显示 2629ms idle，无任何超过 50ms 的长帧），因此这不是
渲染层阻塞，而是 RPC 就绪语义问题。commit `cdea7a5f4` 已把磁盘扫描改为非阻塞分批（`listSessionsAsync`，
每 32 个并发、每 100 个让出事件循环），这解释了为什么主线程空闲——但门仍然等待**全部**扫描完成，
用户感知的延迟没有改变。

根因是门的粒度：`SessionManager.loadSessionsFromDisk()` 索引全部工作区后才 `markReady()`，而
fixture 有 20 个工作区 × 300 会话。实测单个工作区索引约 20ms，20 个合计约 1.1s。用户进入某一个
项目，却要为其余 19 个项目的历史买单。

第二个串行成本在同一条路径上：`initializeSessionManager` 先 `await loadShellEnv()` 再
`sm.initialize()`。前者在 macOS 上启动交互式登录 Shell（`zsh -l -i`）以获取 PATH，实测本机
1.66s——完全取决于用户的 dotfiles。会话发现不需要 PATH，却被排在它后面。分阶段计时（自进程启动）：

| 阶段 | 时刻 | 增量 |
|---|---|---|
| RPC handler 注册完成 | 746ms | +746ms |
| `shell-interactive` → `startRuntime` | 1129ms | +383ms |
| `sm.initialize` 进入 | 3157ms | **+2028ms（登录 Shell）** |
| 活跃工作区分片开门 | 3241ms | +84ms |
| 全部分片开门 | 4549ms | +1308ms（其余 19 个工作区） |

这与 ADR 0006 的运行时所有权模型不一致：一次请求只属于一个 Runtime Domain，其就绪性不应由其他
域的规模决定。ADR 0008 也已确立 Workspace Search 只解析唯一 workspace——它需要的恰好只是该
workspace 的会话（用于过滤 hidden 会话），不需要全局索引。

## 决策

会话运行时就绪从单一全局门改为**按工作区分片**：

- `SessionManager` 为每个工作区维护独立就绪门；某工作区的会话索引完成即开放该工作区。
- 初始化门 RPC 外观从请求上下文解析 workspaceId（已有的 `resolveContextWorkspaceId` 语义），
  只等待该工作区的分片，不等待全局完成。
- 无法解析到具体工作区的请求（跨域或全局语义）继续等待全局门，保持原有保证。
- 磁盘发现优先索引活跃工作区，其余工作区在后台继续；分批让出事件循环的行为不变。
- 登录 Shell 环境发现（macOS 上的 `zsh -l -i`）与会话发现**并行**，不再串行于其前：它只为 Agent
  子进程提供 PATH，会话发现读取 JSONL 与凭据，两者无依赖。Agent 创建处通过
  `whenSubprocessEnvReady` 钩子等待它，原有"子进程启动前环境就绪"的保证不变。
- 阶段划分不变：ADR 0002 的两阶段启动、工作区/文件 RPC 不入门、工作区切换无运行时副作用等约束
  全部保留。本 ADR 只细化第二阶段内部的门粒度与其内部顺序。

## 后果

优点：

- 进入一个项目只等待该项目的会话索引（实测量级 ~20ms），首次搜索/会话请求不再随其他项目的历史
  规模线性劣化。实测首次 `getSessions` 从 2550–2822ms 降至 37–93ms。
- 就绪语义与 ADR 0006 的运行时所有权一致：一个域的规模不再影响另一个域的可用性。
- 冷启动后的首次交互成本从"与全部历史成正比"变为"与当前项目历史成正比"，且不再与用户 dotfiles
  的执行时间耦合。

代价：

- 就绪状态从一个布尔量变为按工作区的映射，`waitForInit` 出现有作用域与无作用域两条路径，实现与
  测试复杂度上升。
- 需要显式定义"未解析到工作区"的回退语义，否则会退化成隐式的部分就绪。
- 跨工作区聚合语义的调用方（若将来出现）必须显式等待全局门，不能依赖任意分片。
- 环境就绪从"初始化完成即成立"变成一个必须被显式等待的前置条件；任何新的子进程启动路径都要经过
  `whenSubprocessEnvReady`，否则会在慢 dotfiles 机器上出现 PATH 竞态。

## 非目标

- 不引入持久会话索引、数据库或 FTS（ADR 0008 的非目标继续适用）。
- 不改变 ADR 0002 的两阶段启动划分，也不把会话 RPC 移出门外。
- 不改变会话 JSONL 的磁盘格式或发现算法本身。
