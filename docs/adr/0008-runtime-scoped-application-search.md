# ADR 0008: 应用搜索编排运行时域内全文检索

状态：Accepted
日期：2026-07-27

## 背景

Activity Rail 的“搜索”原本只把查询发送到当前 workspace 的会话 JSONL。项目名、真实文件内容和
其他项目均不在契约内；服务异常又会被折叠成空结果。UI 名称表达的是应用搜索，实际能力却只是一个
无错误状态的局部会话过滤器。

搜索包含两个正交维度：应用导航知道“有哪些项目”，Runtime Domain 才知道“当前项目有哪些真实
内容”。把二者压进一个跨 workspace 服务会破坏 ADR 0006 的运行时所有权，并要求长期维护隐藏扫描、
跨域缓存或持久索引。

## 决策

- Application Search 由 renderer/AppShell 拥有：使用本地项目目录匹配项目名，并编排当前
  Runtime Domain 返回的结果。
- Workspace Search 由 server runtime 拥有：从 transport context 解析唯一 workspace，搜索该
  workspace 的会话和真实文件；请求不得携带可覆盖所有权的 workspace id。
- 项目元数据复用现有 `uFuzzy` 排名，会话和文件内容复用 `ripgrep`，`cmdk` 只负责呈现和键盘交互，
  不对已排序结果二次过滤。
- 返回值是带身份和定位信息的 typed hits。启动失败、超时和异常退出返回 unavailable，不得伪装成
  “没有结果”。
- 点击会话必须携带原查询进入既有消息高亮与定位链路；点击文件使用真实路径进入现有文件打开链路。
- 当前不建立持久索引，也不隐式预加载其他项目的会话或文件。只有标准 fixture 上的全局搜索超过
  1 秒预算且 `ripgrep` 已被证明确为瓶颈时，才另立 ADR 选择索引。

## 后果

优点：

- 应用级发现与运行时内容所有权各自单一，远程 workspace 仍沿现有 RPC 路由执行。
- 搜索事实直接来自 JSONL 和项目文件，不引入索引一致性或迁移问题。
- 失败、空结果和加载中成为不同产品状态，诊断不再丢失。

代价：

- 一次查询最多组合本地项目名与当前 workspace 内容；搜索其他项目内容需要先显式切换项目。
- 文件搜索按请求扫描并受超时、文件大小和结果数量限制；若项目规模越过当前预算，需要基于测量重新
  决策索引，而不是追加关键词特例。

## 非目标

- 不提供跨 Runtime Domain 的全文内容聚合。
- 不引入 Elasticsearch、Meilisearch、SQLite FTS 或浏览器内全文索引。
- 不把文件类型、目录名或写作类别编码成搜索权限。
