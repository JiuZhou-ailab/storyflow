# Domain Docs

## Layout

沿用现有 **multi-context** 布局：

- 根 `CONTEXT-MAP.md`：跨领域导航及关系。
- 根 `CONTEXT.md`：共享术语，包括搜索、文档原件与表示、性能。
- `docs/contexts/` 中各领域的 `CONTEXT.md`：对应领域词汇与责任边界。
- `docs/adr/`：现有架构决策。

不创建另一套领域目录或迁移现有词汇表。

## Consumer rules

1. 陌生区域先读根 README 和沿途子系统 README，再读根 context map、共享 glossary 及本次相关领域词汇表。必要时通过现有 context 目录索引补充定位，不因 map 暂未收录而另建文档。
2. 阅读相关 ADR，并核对其 Accepted、修订或 Superseded 状态；被替代的决策不能当成当前约束。
3. 文档用于导航与术语，代码、契约和测试是事实源。结论前补全实际定义、调用方与验证证据。
4. 输出中的领域概念使用词汇表已有名称。新概念只有在职责确实不同且经讨论确认后才进入领域文档。
5. 方案若与有效 ADR 冲突，明确指出冲突和理由，不静默覆盖。
6. 缺失文档时继续核实代码，不为完成 Skill 流程自动补造领域知识；已验证的词汇或决策需要记录时再使用 domain-modeling。
7. 修改后检查相关语义地图是否失效，只同步本次变更影响的层级。
